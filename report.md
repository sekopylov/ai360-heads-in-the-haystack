# Отчёт: цель, план и текущая задача

Дата: 2026-10-07. Подробный план по шагам — в [PLAN.md](PLAN.md).

## 1. Цель

Проверить, сохраняется ли роль «retrieval-голов» из статьи *Retrieval Head Mechanistically Explains Long-Context Factuality* на новой модели и на усложнённой задаче.

Гипотеза:

1. На данных и метрике авторов (в том виде, как она реализована в их коде) Qwen3.5-9B ведёт себя так же, как модели из статьи: голов мало, их маскирование роняет качество сильнее, чем маскирование случайных.
2. При метрике из текста статьи и усложнённом контексте (похожие факты, отвлекающие записи, перефразированные вопросы) набор голов меняется, и это согласуется со статьёй *Query-Focused Retrieval Heads Improve Long-Context Reasoning and Re-ranking*.

## 2. Общий план

| Этап | Что делаем | Результат |
|---|---|---|
| 0 | Прогон **старого кода** авторов на Qwen1.5-14B-Chat на нашей A100 80 ГБ, с выгрузкой данных | Эталон для всех сравнений |
| 1 | Новый код с перехватом матриц внимания, для старых и новых моделей | Пакет с детекцией, маскированием и метриками |
| 2 | Сверка нового кода с эталоном на Qwen1.5-14B-Chat | Подтверждение, что новый код повторяет старый |
| 3 | Qwen3.5-9B на данных и метрике авторов | Проверка первой части гипотезы |
| 4 | Метрика из статьи, QRscore, усложнённые данные | Проверка второй части гипотезы |

Принятые решения:

- Новый код сверяем **с нашим прогоном старого кода**, а не с цифрами статьи и не с авторским `head_score`. Авторские скоры остаются справкой.
- Старая модель — Qwen1.5-14B-Chat, новая — Qwen3.5-9B.
- Сетка длин 1k–30k токенов: её ограничивает старая модель (предел 32k).
- У Qwen3.5-9B матрицы внимания есть только в 8 слоях из 32, поэтому число маскируемых голов сравниваем в долях.

## 3. Текущая задача: этап 0

Добавить в старый код выгрузку данных и прогнать его. Поведение кода не меняем: те же промпты, та же генерация, тот же подсчёт скора.

### 3.1. Подготовка

- [ ] Перенести авторский `source/head_score/Qwen1.5-14B-Chat.json` в `source/head_score_authors/`. Скрипт детекции дописывает результаты в существующий файл, и наш прогон смешался бы с авторским.
- [ ] `--model_name_suffix` **не использовать**: суффикс добавляется к имени модели, и ветка чат-шаблона (сравнение со строкой `"Qwen1.5-14B-Chat"`) перестаёт срабатывать.
- [ ] `--model_provider` оставить по умолчанию (`LLaMA`). При этом для поиска конца предложения используются id точек из словаря Llama, и на Qwen игла вставляется не на границе предложения. Оставляем как есть, фактическую позицию иглы пишем в выгрузку.
- [ ] Окружение авторов: `transformers==4.37.2`, `torch==2.0.1`. Записать, стоит ли `flash-attn`, версии библиотек и коммит.

### 3.2. Выгрузка из скрипта детекции

Файл: `source/retrieval_head_detection.py`. Один `.npz` на пример в `source/results/dump/<модель>/detect/`.

| Поле | Размер | Зачем |
|---|---|---|
| `input_ids` | длина промпта | новый код должен собрать тот же вход |
| `output_ids` | до 50 | сверка генерации |
| `needle_start`, `needle_end` | 2 числа | границы иглы, как их нашёл старый код |
| `rouge` | число | фильтр «успешный пример» |
| `top1_idx` | шаги × слои × головы | позиция top-1 внимания |
| `top1_val` | шаги × слои × головы | значение top-1 |
| `needle_mass` | шаги × слои × головы | сумма внимания на иглу; нужна для метрик этапа 4 |
| `retrieval_score` | слои × головы | скор примера, как его посчитал старый код |

Дополнительно на 9 примерах (длины около 1k, 10k, 30k × глубины 0, 50, 100):

- полные строки внимания для первых 3 шагов генерации, `float16`. На 30k токенов это около 300 МБ на пример.

Объём основной выгрузки — около 0.5 ГБ на 600 примеров. Папка `results/` в `.gitignore`, так что выгрузки в git не попадут; хранить их нужно отдельно.

### 3.3. Выгрузка из скрипта маскирования

Файл: `source/needle_in_haystack_with_mask.py`. Один `.npz` на пример в `source/results/dump/<модель>/mask_<конфигурация>/`.

- `input_ids`, `output_ids`, `rouge`;
- `block_list` — какие головы были замаскированы на этом примере. Случайные головы скрипт выбирает **заново на каждом примере**, без seed.

Единственная добавка к поведению: аргумент `--seed`, который фиксирует `random` и пишется в выгрузку.

### 3.4. Прогоны

Все команды — из папки `source/`.

Детекция (3 иглы × 20 длин × 10 глубин = 600 примеров):

```bash
python -u retrieval_head_detection.py --model_path Qwen/Qwen1.5-14B-Chat -s 1000 -e 30000 --context-intervals 20
```

Маскирование (20 длин × 10 глубин = 200 примеров на конфигурацию; игла про Сан-Франциско, эссе Пола Грэма):

```bash
python -u needle_in_haystack_with_mask.py --model_path Qwen/Qwen1.5-14B-Chat -s 1000 -e 30000 --context-intervals 20 --mask_topk 0
```

Конфигурации `--mask_topk`:

- без маски: `0`;
- top-головы: `10`, `20`, `30`, `50`, `100`;
- случайные: `-10`, `-20`, `-30`, `-50`, `-100`, по 3 seed.

Всего 1 + 5 + 15 = 21 конфигурация, 4200 примеров. Скрипт берёт головы из `head_score/Qwen1.5-14B-Chat.json`, то есть из нашей детекции, поэтому маскирование запускается после неё.

Порядок:

1. Пробный запуск детекции на 2 длинах и 2 глубинах; проверить, что выгрузка пишется и читается.
2. Полная детекция.
3. Маскирование.

### 3.5. Что проверить по результатам

- [ ] Где фактически оказывается игла относительно заданной глубины.
- [ ] Совпадает ли `retrieval_score`, пересчитанный из `top1_idx` и `output_ids`, со скором старого кода. Если да, выгрузки достаточно для сверки нового кода.
