# Метрика `needle_attention_mass_v1`

Разбор по коду ветки `c0` (папка `updated/`, состояние на коммит `95dfd4d`). Ничего не запускалось: описание составлено по коду, конфигам запусков и отчёту `updated/REPORT.md` этой ветки.

## Что измеряет

Какую долю внимания голова отдаёт ответу внутри иглы в те моменты, когда модель выдаёт токен, встречающийся в этом ответе.

Отличие от метрики статьи: там голове засчитывается шаг, только если её **самая сильная** позиция внимания попала в иглу и токен там совпал с генерируемым. Здесь берётся **вся масса** внимания на игле, без требования быть первой и без проверки, на какой именно токен голова смотрит.

## Определение

Обозначения для одного примера:

- `S` — отрезок промпта с ответом внутри иглы (например, `eat a sandwich and sit in Dolores Park on a sunny day`), позиции `[start, end)`;
- `T` — множество номеров токенов, встречающихся в `S`;
- `y_t` — токен, сгенерированный на шаге `t`;
- `a_t(h, j)` — внимание головы `h` на позицию `j` на том проходе модели, который выдал `y_t`.

Масса головы на шаге:

```
m_t(h) = сумма a_t(h, j) по j из [start, end)
```

Учитываются только шаги, где `y_t` входит в `T`. Скор головы на примере — среднее по таким шагам:

```
score(h) = среднее m_t(h) по шагам t, где y_t ∈ T
score(h) = 0, если таких шагов нет
```

Итоговый скор головы — среднее `score(h)` по успешным примерам (ROUGE-1 recall строго больше 50). Диапазон от 0 до 1.

## Как считается в коде

| Шаг | Где | Что происходит |
|---|---|---|
| 1. Отрезок иглы | `experiment/locator.py`, `LegacyOverlapLocator` | Ответ токенизируется отдельно; по промпту идёт окно той же длины; берётся первое, где совпало больше 90% множества токенов |
| 2. Внимание | `attention/backend.py`, `observable_eager_attention` | На шагах генерации внимание считается явно: логиты, softmax в fp32, затем приведение к точности модели (fp16) |
| 3. Масса на шаге | `attention/controller.py`, `record` | Берётся строка последнего запроса, значения на `[start, end)` суммируются в fp32 на видеокарте; на процессор уходит одно число на голову |
| 4. Отбор шагов | `experiment/scoring.py`, `NeedleAttentionMassCollector.on_step` | Шаг пропускается, если сгенерированный токен не входит в `T` |
| 5. Скор на примере | там же | Масса обрезается до `[0, 1]`, накапливаются сумма и число шагов, скор равен их отношению |
| 6. Сохранение | `retrieval_head_detection.py` | В JSON примера пишутся скоры всех голов и число учтённых шагов (`retrieval_qualifying_steps`) |
| 7. Сводный файл | `aggregate_head_scores.py` | Без видеокарты: отбираются примеры с ROUGE > 50, для каждой головы собирается список скоров по примерам |

Формат итогового файла `head_scores_needle_attention_mass_v1.json` — как у авторов статьи: ключ `слой-голова`, значение — список скоров по примерам. Рейтинг строится по среднему списка. Наш `rh.run --mask_file` читает такой файл без правок.

## Особенности подсчёта

- **Отбор шага идёт по номеру токена, а не по смыслу.** В ответе иглы есть служебные слова (`a`, `and`, `in`, `on`). Любой шаг, где модель выдала такой токен, учитывается — даже если она в этот момент не воспроизводит иглу.
- **Проверяется только масса на отрезке.** Куда именно внутри отрезка смотрит голова и совпадает ли там токен с генерируемым, не важно.
- **Нулевая масса тоже входит в среднее.** Голова, которая на подходящих шагах не смотрит на иглу, получает низкий скор, а не пропуск.
- **Отрезок — ответ, а не вся игла.** Внимание на начало фразы иглы (`The best thing to do in San Francisco is`) в массу не входит.
- **Отрезок найден нечётким поиском.** Он может быть сдвинут или не той длины, если отдельная токенизация ответа не совпала с токенизацией внутри текста. Сдвиг напрямую меняет массу.
- **Среднее средних.** Сначала усреднение по шагам внутри примера, потом по примерам. Пример с тремя подходящими шагами весит столько же, сколько пример с тридцатью.
- **Точность.** Суммируются вероятности, уже приведённые к fp16.
- **Thinking.** При режиме `all_decode_tokens` учитываются все шаги генерации, включая рассуждение в `<think>`.

## Два файла от Михаила

Оба файла называются одинаково и получены одной и той же метрикой на одной сетке, но в разных прогонах.

| | Первый файл | Второй файл |
|---|---|---|
| Прогон в `c0` | `qwen3-8b-survey` | `qwen3-8b-no-thinking-survey` |
| Thinking | включён | выключен |
| Ядро внимания на контексте | `sdpa_memory_efficient` | `sdpa_flash` |
| 5 лучших голов | 22-23, 23-10, 13-15, 7-4, 19-24 | 29-11, 22-23, 24-22, 13-13, 13-29 |
| Лучший скор | 0,376 | 0,863 |
| У нас в репозитории | `data/head_scores/head_scores_needle_attention_mass_v1.json` | `data/head_scores/head_scores_needle_attention_mass_v1_2.json` |

Общее для обоих прогонов:

- Qwen3-8B, fp16, все шаги генерации (`all_decode_tokens`), лимит ответа 2048 токенов;
- 27 примеров: 3 иглы × длины 8000, 16000, 30000 × глубины 15, 45, 75;
- `--context-seed 42`: файлы стога перемешаны;
- во втором прогоне все 27 примеров прошли порог ROUGE; в первом, судя по 27 значениям на голову в файле, тоже.

Почему скоры в первом файле примерно вдвое ниже: с включённым thinking подходящие шаги набираются и внутри рассуждения, где модель выдаёт токены из иглы, не глядя на неё. Это моё объяснение по коду, прогоном оно не проверено. Сами авторы `c0` отмечают, что между прогонами сменилось ещё и ядро внимания, так что это не чистое сравнение «с thinking и без».

Пересечение двух рейтингов по отчёту `c0`: 1 общая голова из 4 лучших, 10 из 16, 58 из 64, 112 из 120.

Для наших прогонов без thinking согласован по условиям второй файл.

## Связь с другими метриками

По отчёту `c0`, на 1152 головах и 27 примерах первого прогона:

| Пара | Пирсон | Спирмен |
|---|---|---|
| `legacy` и `multiset` | 0,974 | 0,999 |
| `legacy` и масса внимания | 0,681 | 0,755 |
| `multiset` и масса внимания | 0,669 | 0,757 |

`legacy` — скор из кода авторов статьи (наш `copy_count`), `multiset` — его вариант с ограничением повторов. У них 798 голов имеют нулевой скор, у массы внимания нулевых нет: она ранжирует все головы, а не только копирующие.

## Отличие от нашего `needle_mass`

| | `needle_mass` в `rh/metrics.py` | `needle_attention_mass_v1` в `c0` |
|---|---|---|
| Масса на шаге | сумма внимания на отрезке ответа | то же |
| Какие шаги усредняются | все шаги ответа | только шаги, где токен есть в игле |
| Отрезок | точный, по символьным смещениям | нечёткий поиск |
| Точность значений | fp32 | fp16 |
| Число примеров в детекции | 600, глубины 0–100 | 27, глубины 15, 45, 75 |

Числа двух метрик напрямую не сравнимы: наша делит на большее число шагов и поэтому ниже.

## Как посчитать у нас

Метрика добавлена в `rh/metrics.py` под именем `needle_attention_mass`: это `SpanMass` с отбором шагов (`span_tokens_only=True`). Она считается в любом прогоне с `--save compact` вместе с остальными метриками голов, отдельного запуска не требует. Результат — `head_score_needle_attention_mass.json` рядом с `head_score_copy_count.json`, в том же формате.

Сравнение рейтингов по лимитам длины ответа для этой метрики: `python -m rh.limits <папка прогона> --metric needle_attention_mass`.

Оговорка: файлы шагов детекции Qwen3-8B уже удалены после подсчёта метрик (`--consume`), поэтому для этой метрики детекцию придётся прогнать заново. Результат будет отличаться от файлов Михаила точным отрезком иглы, точностью fp32 и сеткой примеров.
