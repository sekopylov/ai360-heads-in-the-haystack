Вторая статья для сверки: *Query-Focused Retrieval Heads Improve Long-Context Reasoning and Re-ranking* (QRHead).

Оборудование: 1 × A100 80 ГБ.

## 1. Что хотим получить

1. **Эталон на нашем железе.** Прогон оригинального кода авторов на Qwen1.5-14B-Chat. Все дальнейшие сравнения идут с ним, а не с цифрами из статьи.

4. **Проверка гипотезы:** при метрике из статьи и усложнённом контексте набор «retrieval-голов» меняется, и это согласуется с QRHead.

## 2. Модели

| | Qwen1.5-14B-Chat | Qwen3.5-9B |
|---|---|---|
| Роль | проверка кода (есть в статье) | новая модель |
| Слои с матрицей внимания | 40 из 40 | 8 из 32 (остальные 24 — Gated DeltaNet) |
| Голов на слой | 40 | 16 |
| Всего голов для метрики | 1600 | 128 |
| Максимум контекста | 32k | 262k |
| Веса (bf16) | ~28 ГБ | ~19 ГБ |

Следствия:

- Сетку длин задаёт старая модель: **1k–30k токенов** для обеих.
- Число маскируемых голов сравниваем **в долях** от общего числа, а не в штуках.
- У Qwen3.5-9B метод видит только 8 слоёв. Что делают DeltaNet-слои, он не показывает; это ограничение пишем в выводах.
- Данные по Qwen3.5-9B взяты из `config.json`, код модели не проверен (шаг 4.1).

Запасная пара для сырого промпта без чат-шаблона: Qwen1.5-14B и Qwen3.5-9B-Base.

## 4. Этап 1. Новый код

### 4.1. Первая проверка (до написания всего остального)

- [ ] Загрузить Qwen3.5-9B в свежих `transformers`, посмотреть класс и модули внимания.
- [ ] Проверить, подменяется ли функция внимания через `AttentionInterface`, и какие слои отдают матрицы.
- [ ] Если нет — перехват через обёртку над `forward` модулей внимания.

### 4.2. Перехват матриц

Одна своя функция внимания с тремя режимами:

- **быстрый** — обычный `scaled_dot_product_attention`, без захвата;
- **захват** — считает веса явно и отдаёт их после softmax в коллектор;
- **маска** — зануляет логиты заданных голов до softmax, как в оригинале. Вариант «занулить выход головы» — отдельным флагом.

### 4.3. Двухфазный прогон

1. Префикс (контекст) — быстрый режим, заполняет KV-кэш.
2. Хвост (вопрос и шаги генерации) — захват и/или маска.

Полная матрица на 30k токенов в память не помещается; строки хвоста занимают мегабайты. Их хватает и для retrieval score, и для QRscore.

### 4.4. Что сохраняем

Матрицы не храним. На каждый пример, шаг, слой и голову:

- позиция и значение top-1 внимания;
- сгенерированный токен;
- масса внимания на иглу и на каждый отвлекающий фрагмент.

Метрики считаются из этих записей офлайн.

### 4.5. Модули

| Модуль | Что делает |
|---|---|
| `models/registry` | Описание модели: id, тип промпта, выключение thinking, стоп-токены, максимум контекста. Число слоёв и голов читается из модели |
| `attn/capture` | Функция внимания, переключение режимов, список слоёв с вниманием |
| `data/haystack` | Сборка контекста, иглы, отвлекающие факты; границы фрагментов через `offset_mapping` |
| `run/generate` | Двухфазный прогон, жадная генерация |
| `metrics/retrieval_legacy` | Скор в точности как в коде авторов |
| `metrics/retrieval_paper` | Скор как в статье: доля уникальных токенов иглы, скопированных головой |
| `metrics/qr_score` | Метрика из QRHead |
| `cli/detect`, `cli/mask`, `cli/compare` | Запуск детекции, маскирования, сравнение наборов голов |

Режим `legacy` повторяет все пункты из 3.4.

## 7. Этап 4. Проверка гипотезы

Дизайн 2 × 2 для каждой модели:

| | простые данные | усложнённые данные |
|---|---|---|
| метрика из кода | этапы 2–3 | новое |
| метрика из статьи | пересчёт офлайн | новое |

Усложнения — отдельными условиями, не смесью:

- похожие факты (конкурирующие иглы);
- отвлекающие записи;
- перефразированные вопросы.

Что измеряем:

- [ ] Ранговая корреляция скоров голов и пересечение top-k между условиями.
- [ ] Перекрёстное маскирование: головы, найденные на простых данных, маскируем на сложных, и наоборот.
- [ ] QRscore на тех же данных; пересечение трёх наборов голов.

Контроль:

- Игл для детекции нужно больше трёх: 20–50, с доверительными интервалами.
- На сложных данных успешных примеров меньше. Сравниваем на примерах, где модель ответила в обоих условиях, и везде указываем их число.
- При перефразировании модель отвечает не дословно, и скор по копированию падает сам по себе. Это нужно отделять от смены голов.
- Критерии «разошлись / не разошлись» фиксируем до запуска.
